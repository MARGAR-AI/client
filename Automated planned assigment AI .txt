Automated Planned Assignment of AI Providers on Projects


I. Objective


Develop a web application to automate the assignment of service providers (AI providers) to planned projects, ensuring efficiency and optimal allocation based on predefined criteria.


II. Key Features
* Automated and adjustable allocation of AI providers.
* Matching logic based on daily workload and provider availability.
* Priority assignments based on experience (TotalImageDelivered) and quality (AvgEdits).
* Clear display of projects, providers, and resource allocation.
* Visualization of needed vs. allocated resources (e.g., Gantt chart).
* Manual adjustment of provider's daily capacity.
III. Data Sources
1. Resource Allocation Planning Sheet:
   * Link: Planning ressource allocation/ CONCEPTION
   * Fillment source: Automatic + manual modification possible.
   * Fillment rules: Each line is the assignment of 1 provider to a specific project launch.
   * Headers:
      * Assignment ID
      * Provider's Name
      * Client
      * Project ID
      * Project Name
      * Batch
      * Previsional launch date
      * Previsional delivery date
      * Service
      * Qty
      * % of project
   * Assignment ID Generation: Provider's Name + Project ID + Batch + Row Number
2. Delivery Planning Sheet:
   * Link: Planning ressource allocation/ CONCEPTION
   * Fillment source: Web application input + spreadsheet synchronization. (CSV upload for phase 1)
   * Fillment rules: Each line is a project (or part of it) to be launched.
   * Headers:
      * Project ID
      * Client
      * DealID (pulled from "Client Deal ID list")
      * Project Name
      * Batch
      * Previsional launch date
      * Previsional final date
      * Previsional First delivery date
      * Status
      * Service
      * Categories of Modeling
      * Comments
      * Qty
      * % of allocated
      * Confidence Level
      * Last Modified
      * Change Reason
      * Notified People
      * Project Manager
      * Duration (Calculated)
3. Availability Sheet:
   * Link: Planning ressource allocation/ CONCEPTION
   * Source: Another web application in progress.
   * Rules: Each line is a provider's availability.
   * Headers:
      * Provider's ID
      * Name
      * Role (Filter for "AI Creator")
      * Available Now (Not used)
      * Available In Future (TRUE)
      * Start Date
      * End Date
      * No longer Available (TRUE to exclude)
      * Submission Date (Not used)
      * Message (Not used)
   * Virtual Columns (for calculations):
      * Duration (days between Start and End, excluding weekends)
      * Capacity for available period (Duration * Daily capacity)
      * Capacity per week (5 working days)
4. AI Creator Workload Sheet:
   * Link: genai_creators_workload
   * Source: AI image creation platform.
   * Rules: 1 line = information for 1 AI Creator.
   * Headers:
      * ImageCreatorUserName (match Availability form)
      * orgCode (Client’s name)
      * ActiveWorkloadSKUsLaunched (2 images/SKU - variable)
      * ActiveWorkloadSLUsQC (Not used)
      * TotalSKUs (Not used)
      * TotalImageDelivered (Prioritization)
      * AvgEdits (Prioritization)
IV. Matching Logic
1. Identify projects needing providers based on launch date.
2. Compare daily workload against provider availability.
3. Assign providers where capacity allows.
4. Display unassigned demand (shortages) in red.
V. Priority Assignments
* TotalImageDelivered: Prioritize by experience (more images = more experienced).
* AvgEdits: Prioritize by quality (fewer edits = more qualified).
* Assign providers available for the entire project duration.
* Fill gaps using partial availability if needed.
* Balance workload to avoid over-assignment.
VI. Display
* Display all upcoming projects (roadmap, list, etc.).
* Each project shows:
   * % of fitness of capacity
   * Number of images to create
   * Number of affected providers
* Clicking a project shows:
   * List of automatically assigned providers
   * Project details
   * Display of available providers for the project period.
   * Ability to cancel, modify image qty, remove/replace providers (drag-and-drop).
* Visualize needed resources vs. project needs:
   * Example: Gantt chart (bar thickness = AI Images, length = timeline, fullness = % of allocated resources).

* A provider can do 2 Images per day (5 working days/week).

* Daily capacity of the provider is manually adjustable.

# Detailed Description of the AI Provider Assignment Application


## Application Overview


This is a web application for managing AI provider assignments to projects. The application consists of a Node.js Express backend and a React frontend with Material UI components. It's designed to help manage resources (AI creators) and assign them to various projects based on their availability and capacity.


## Core Functionalities


1. **Project Management**
   - View a list of all projects with details like ID, name, client, dates, and required images
   - Calculate and display allocation status for each project
   - Export project data to CSV format
   - View detailed information for individual projects


2. **Provider Management**
   - View and manage AI creators/providers
   - Track provider availability periods
   - Set daily capacity for providers
   - Group providers by name and display their availability periods


3. **Assignment Management**
   - Assign providers to specific projects
   - Calculate percentage of project allocated to each provider
   - Export assignments to CSV format
   - View all assignments across all projects


4. **Timeline Visualization**
   - Gantt chart view of projects and assignments
   - Visual representation of project timelines
   - Zoom and navigation controls for the timeline


5. **Data Import/Export**
   - Import data from CSV files
   - Export project and assignment data to CSV files in specific formats


## Technical Architecture


1. **Backend (Node.js/Express)**
   - API endpoints for projects, providers, and workload data
   - CSV parsing for data import
   - Serving static files from the client build directory


2. **Frontend (React)**
   - Material UI components for the interface
   - React Router for navigation
   - Axios for API requests
   - Date-fns for date manipulation


3. **Data Storage**
   - CSV files for data persistence:
     - `Planning ressource allocation_ CONCEPTION  - Delivery Planning (1).csv` (Projects)
     - `Planning ressource allocation_ CONCEPTION  - Availability.csv` (Providers)
     - `genai_creators_workload - genai_creators_workload.csv` (Workload)


## Key Components


1. **ProjectList.js**
   - Displays all projects in a table
   - Shows allocation status with progress bars
   - Provides export functionality for project data


2. **ProjectDetail.js**
   - Shows detailed information for a specific project
   - Allows assigning providers to the project
   - Displays assigned providers and their allocation


3. **ProviderManagement.js**
   - Lists all providers grouped by name
   - Shows availability periods for each provider
   - Displays assignments in an accordion format


4. **AssignmentList.js**
   - Shows all assignments across all projects
   - Provides export functionality for assignment data
   - Links to project details


5. **ProjectGantt.js**
   - Visual timeline of projects
   - Date navigation and zoom controls
   - Project status visualization


## Errors Encountered and Lessons Learned


1. **Port Conflicts (EADDRINUSE)**
   - **Error**: `Error: listen EADDRINUSE: address already in use :::5000`
   - **Cause**: Multiple instances of the server trying to use the same port
   - **Solution**: Kill all Node.js processes before starting the server
   - **Learning**: Always ensure no other processes are using the required port before starting the server


2. **Missing Dependencies**
   - **Error**: `Error: Cannot find module 'express'`
   - **Cause**: Dependencies not installed or node_modules not found
   - **Solution**: Run `npm install` in both root and client directories
   - **Learning**: Always check that all dependencies are properly installed before running the application


3. **React and MUI Version Compatibility Issues**
   - **Error**: Multiple `Module not found` errors for MUI icon components
   - **Cause**: Incompatible versions of React (v19) and Material UI
   - **Solution**: Downgrade React to a compatible version or upgrade MUI
   - **Learning**: Check compatibility between major libraries before upgrading


4. **Client Build Issues**
   - **Error**: `sh: react-scripts: command not found`
   - **Cause**: react-scripts not installed or not in PATH
   - **Solution**: Install react-scripts or run `npm install` in the client directory
   - **Learning**: Ensure all dev dependencies are installed before building


5. **Date Parsing Issues**
   - **Cause**: Inconsistent date formats in CSV data (DD/MM/YYYY)
   - **Solution**: Create a custom date parsing function using date-fns
   - **Learning**: Always handle date parsing carefully, especially with international formats


6. **Missing CSV Files**
   - **Cause**: CSV files not found in the expected location
   - **Solution**: Ensure all required data files are in the correct location
   - **Learning**: Validate file paths and provide clear error messages for missing files


7. **Incomplete Client Build**
   - **Cause**: Client build directory missing key files
   - **Solution**: Properly build the client application with `npm run build`
   - **Learning**: Verify the build output contains all necessary files

   - Backend runs on port 5000

   - Run `npm install` in the root directory
   - Run `npm install` in the client directory

   - Add validation for date formats


5. **Update Client Code**
   - Fix date parsing issues in components

   - Add error boundaries to catch runtime errors


6. **Testing Strategy**

   - Test the client components with mock data
